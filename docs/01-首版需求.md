# 首版需求与阶段门禁

## 产品目标

面向开发者的桌面编码 Agent，长期支持多模型、企业集成、自定义执行策略。采用 Electron、React、C#/.NET 与 Microsoft Agent Framework。所有产品文案、文档、维护者编写的错误说明使用中文。

## 首版用户流程

选择本地 Git 项目，配置模型，创建任务；Agent 搜索和读取代码，申请修改或命令执行，用户审批后执行；展示真实文件差异和测试结果。支持取消任务和重新打开历史。

## 范围

- 单 Agent 自主编码循环；MAF Harness 通过自有适配层接入。
- 首批工具：文件列表、文本搜索、分段读取、带旧内容校验的补丁、命令执行、Git 状态和差异。
- 本地 Worker 独立进程；SQLite 保存任务、运行与事件。
- OpenAI 兼容接口及 Ollama；模型必须显式配置，分别验证工具调用能力。
- 默认要求审批文件修改和命令执行；读取范围受工作区策略限制。
- API Key 直接保存在本机服务配置中，不写入会话、事件或源代码。

暂不包含自动提交推送、云端多租户、自动发布和多 Agent。终端先实现构建与测试输出，交互式 PTY 另行实现。

## 顺序验收

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| 1 | 需求、架构、协议、固定版本 MAF 验证程序 | 构建和离线契约测试通过；真实模型流式调用并调用工具成功，具备取消与会话序列化验证 |
| 2 | Electron 与 Worker、事件流、SQLite | 真实请求、取消、崩溃提示、重启历史恢复通过 |
| 3 | 搜索、读取、补丁、命令、Git、审批与差异界面 | 在隔离样例项目中修复失败测试，确认实际补丁和结果；越界与取消检查通过 |
| 4 | 权限、超时、日志脱敏、中断核对、预算与上下文 | 故障注入通过，不重复执行外部副作用，不覆盖用户后续修改 |
| 5 | 双提供商和评测集 | 两个真实提供商完成同一组任务，报告成功率、人工介入、耗时与用量；无数据不得记作通过 |

前一阶段通过后再进入下一阶段。缺少凭证、服务或模型属于外部验收阻塞；离线测试与真实验收分别记录，不以模拟完成替代真实通过。

## 用户确认的验收调整

2026-09-12：真实验收使用 Routin 的 OpenAI 兼容接口与用户指定模型。Ollama 连接和真实任务评测按用户要求延后；第 5 阶段继续实现两个提供商的配置支持，真实评测只要求 Routin，Ollama 必须标记为“用户要求跳过”，不得记为通过。
