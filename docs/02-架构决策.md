# 架构决策

## ADR-001：桌面端和 Agent 执行分离

Electron 主进程负责启动、停止本地 .NET Worker，并校验来自渲染进程的请求。React 通过受限 preload API 访问能力，禁用 Node 集成并开启上下文隔离。第一版 Worker 通过标准输入输出通信，不开放本地 HTTP 端口。标准输出仅包含协议消息，诊断日志使用标准错误。

## ADR-002：MAF 置于适配层

使用 .NET 10 和固定版本 Microsoft.Agents.AI.Harness 1.21.0。核心任务、权限和事件模型不引用 MAF 类型。Harness 负责模型与工具循环，产品层负责审批、预算、工作区、凭证、状态及副作用核对。默认关闭 Harness 的自动工具审批、文件记忆、Skills 和网络搜索；仅注册经过产品工具层校验的工具。

阶段 1 的探针是技术验证，允许直接使用 MAF 会话类型；它不是未来客户端协议。生产协议只暴露自有 DTO。

## ADR-003：本地优先

本地 SQLite 保存任务和事件。以后产品服务采用 ASP.NET Core、EF Core 和 PostgreSQL，云端实时通信可用 SignalR。执行器依旧独立。首阶段不增加空的云端服务和调度基础设施。

## ADR-004：模型配置与秘密分离

首批支持 OpenAI 兼容 Chat Completions 接口与 Ollama 的兼容接口。共享传输不代表同一提供商，也不保证模型具有相同能力。配置包含提供商类型、Base URL、模型、工具和流式能力声明；密钥使用环境变量名引用。桌面阶段增加系统凭证存储，后端和 renderer 不记录明文凭证。

OpenAI 兼容远程接口必须使用 HTTPS；HTTP 只允许回环地址。禁止 URL 用户信息、查询字符串和片段，避免把凭证放入地址和日志。不自动添加或猜测模型与远程路径。Ollama 默认回环地址可使用 `/v1/`；连接失败应明确失败，不切换到模拟模型。

## ADR-005：任务不等于一次执行

Task 表示用户目标；Run 表示一次具体执行。继续、重试和更换模型创建新 Run，关联前序执行。事件按 Run 的单调 sequence 保存并补发。终态包含 completed、failed、cancelled、interrupted；恢复默认核对并显式继续，不重放副作用工具。

## ADR-006：权限与隔离边界

工具按参数校验、路径解析、权限判断、具体审批、执行、结果记录的顺序运行。防止 `..`、绝对路径、符号链接及 Windows junction 越界。路径检查不等价于 OS 沙箱，任意 shell 命令即使工作目录受限仍能访问用户其他文件；第一版本地命令仅供可信项目并逐次审批。云端开放不可信执行前必须引入 OS 级沙箱。

补丁和撤销均校验当前内容哈希，避免覆盖用户后续修改。命令需要总时限、输出上限和进程树终止。工具执行结果、工作区版本与恢复决策独立于 MAF 检查点保存。
